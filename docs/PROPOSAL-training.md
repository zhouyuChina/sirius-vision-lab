# sirius-vision-lab 提案：可训练的图像识别能力 + 训练管理系统

> 状态：草案 v1（2026-10-01），待周宇评审。
> 前置阅读：../README.md（能力基线与 API 评测路线）。

## 1. 一句话定位

**用 API 大模型当"标注老师"，训练自己的小型专用模型做在线推理；配一套开源标准件拼装的训练管理系统管数据、实验和模型。**

不训练大模型，不自研训练平台。

## 2. 为什么是"微调小模型"而不是"微调 VLM"

| 维度 | 微调小型分类模型（推荐） | LoRA 微调 VLM（7B 级） | 纯 API 调用 |
|---|---|---|---|
| 典型任务 | 服饰属性多标签、白底图质检、类目归一 | 开放式描述生成 | 同左 |
| 算力需求 | 单卡 4090 × 2-6h，¥10-50/次 | A100 40G × 数小时，¥30-100/次 | 0 |
| 推理成本 | ~¥0.0001/张（CPU 可跑） | GPU 常驻 | ¥0.01-0.03/张 |
| 延迟 | 10-50ms | 500ms+ | 1-5s |
| 幻觉风险 | 无（封闭标签集） | 有 | 有 |
| 数据可私有 | ✅ 模型+数据全自有 | ✅ | ❌ 图出第三方 |
| 精度上限 | 封闭任务可超 API（领域内） | 最高 | 高但不可控 |

**判断依据**：我们的识别任务是封闭标签集（颜色/袖长/领型/质检判定），不需要通用理解能力。
月推理量超过 5-10 万张后，自有小模型的成本和稳定性优势是碾压性的。旺销王管线如果要
批量过图（一个店铺动辄数千 SKU × 6 图），API 路线扛不住量，也没法承诺 SLA。

VLM 微调作为**兜底路线**保留：小模型在某任务上精度不达标时再上，不是首选。

## 3. 技术路线（蒸馏式）

```
┌─────────────────────────────────────────────────────────┐
│ 数据飞环                                                 │
│                                                         │
│  原始图片 ──► API 标注机(GLM/Claude) ──► 人工抽检(5-10%)  │
│                (prompt+schema 复用 vision-lab 评测资产)   │
│                    │                                     │
│                    ▼                                     │
│              金标数据集(版本化) ──► 训练(AutoDL 4090)      │
│                    │                       │             │
│                    │                       ▼             │
│                    │              模型注册表 ──► 推理服务   │
│                    │                       │   (CPU/廉价GPU,│
│                    ▼                       │   部署在自有   │
│              线上badcase回流 ───────────────┘   服务器)    │
└─────────────────────────────────────────────────────────┘
```

关键点：**API 评测和 API 标注是同一套资产**。vision-lab 已规划的 P0 评测（prompt/schema/
结构化输出）直接复用为标注机的配置，一份投入两处收益。

### 模型选型（首批）

| 任务 | 模型 | 说明 |
|---|---|---|
| 服饰属性多标签 | CLIP ViT-B/16 图像塔 + 线性探针；或 ConvNeXt-Tiny 微调 | 少样本冷启动 CLIP 更稳，样本>5k 后全量微调 |
| 主图质检（白底/水印/构图） | ConvNeXt-Tiny 二/多分类 | 简单任务，快速达标 |
| 类目归一（平台类目映射） | CLIP zero-shot 起步 → 探针 | 类目体系是文本，CLIP 天然契合 |

框架：PyTorch Lightning（训练循环结构化、日志/回调/断点续训全，是"可管理"的地基）。

## 4. 训练管理系统：开源标准件 + 薄胶水

不自研平台，不买 SaaS（数据出境 + 订阅费，双重否决）。

| 层 | 选型 | 角色 | 为什么 |
|---|---|---|---|
| 标注 | **Label Studio**（自建） | 标注任务分发、人工抽检界面、金标维护 | 事实标准，支持图像分类/多标签/边界框，有 Python API 可编程造任务 |
| 实验/模型 | **MLflow**（自建） | 实验跟踪（超参/指标/产物）、模型注册表、版本对比 | 原生方案，PyTorch Lightning 一行接入 |
| 数据集版本 | **DVC** | 大文件（图片/权重）版本化，git 管元数据 | 图片不适合进 git，DVC 是标准解 |
| 算力对接 | **AutoDL**（按需租） | 4090 ¥2.4-3.5/hr，训练完即释放 | 国内平台支付宝直付，镜像预装 PyTorch |
| 胶水层 | 自研 ~2k 行 Python | 打通"标注→数据集→提交训练→回写指标→模型发布" | 唯一需要写的代码，CLI 优先，Web 后补 |

### 胶水层 MVP 功能清单（CLI）

```
vl dataset create <name> --source <dir|labelstudio-export>
vl dataset stats <name>                    # 类别分布/泄漏检查
vl train submit <dataset>@<ver> --task garment-attrs --gpu 4090
vl train status / vl train logs <run-id>
vl model register <run-id> --stage candidate
vl model eval <model> --gold <gold-set>    # 对金标集出报告
vl model deploy <model> --target prod      # 推理服务发布
vl annotate auto <dataset> --teacher glm   # API 标注机批量跑
vl annotate review                         # 生成 Label Studio 抽检任务
```

### 推理服务

- FastAPI + ONNX Runtime（小模型 CPU 推理足够，101 或数据节点直接跑）
- 各业务项目（旺销王管线、Ozon 刊登、质检）统一调这个 HTTP 服务，不直连 API 大模型
- 置信度低于阈值的自动降级到 API 大模型（人机结合，兜底幻觉）

## 6. 数据合规（硬边界，来自合同核实）

昕派合同 2026-07-28 版：
- **6.2**：甲方商品数据、运营数据所有权归甲方（昕派）
- 终止后 30 日内要导出归还并删除备份
- **无任何训练授权条款**；6.3 提到"算法优化成果"归属需另行书面约定

结论与对策：

1. **MVP 阶段**：只用公开数据集（DeepFashion2、Fashion-MNIST 类）+ 自有拍摄/合成数据，
   管线全跑通，不碰客户图。
2. **商用前**：与昕派签补充协议，把"授权乙方在提供服务范围内使用商品图片优化识别模型"
   写进去。可以包装成卖点：**数据不出境、模型专属、终止可删**。
3. 训练管理系统的数据集管理里必须有 `license` 字段（customer-authorized / public / self-owned），
   无授权数据集禁止进入训练管线——这是胶水层要强制的，不是口头约定。

## 8. 阶段路线

| 阶段 | 内容 | 产出 | 预估 |
|---|---|---|---|
| **0 蒸馏可行性**（复用 vision-lab P0） | 24 张 wxw 图跑 GLM vs Claude 结构化标注对比，人工全检 | 标注机 prompt+schema 定版；API 标注一致率报告 | 1-2 天 |

| **2 管理系统成型** | MLflow+DVC 接入；金标集建立；badcase 回流闭环 | 全量 `vl` 命令；模型注册表可用 | 1-2 周 |
| **3 生产接入** | 推理服务部署；旺销王管线图像识别切到自有模型（灰度） | 生产指标对比报告（成本/延迟/精度 vs API） | 1 周 + 客户协议 |

阶段 0 就是我昨天已排的 P0 评测——路线没变，只是终点从"选个 API"升级成"训练自己的模型"。

## 9. 风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| API 标注质量不足→小模型学错 | 高 | 人工抽检 5-10% 起步；金标集独立于训练集；难例路由 Claude |
| 客户数据授权谈不下来 | 中 | MVP 用公开数据；卖点化谈判（模型专属） |
| 146 服务器不稳定/位置不合规 | 中 | 备选 101（境内阿里云）；DVC remote 可迁移 |
| 小模型精度天花板 | 中 | 兜底路线=LoRA 微调 Qwen-VL；置信度降级 API |
| AutoDL 数据安全 | 低 | 只传脱敏后的训练集（图片本身公开或自有），不传客户敏感信息 |
| 训练管理自研范围膨胀 | 高 | 胶水层锁死 CLI 优先；Web UI 延后到有非技术用户才做 |
